# CrossPlay -> reTerminal Sticky Playground submission

The submitted entry, as sent. `firmwares/crossplay/` is a byte-for-byte copy of
what went into the pull request against
`Seeed-Projects/reterminal-sticky-playground-registry`, minus the firmware
binary (see `.gitignore` for how to fetch it back).

## What the earlier draft got wrong

The staged draft at the workspace root was written on 2026-08-31 against a
reading of the registry that no longer matches it. Four things changed:

1. **The metadata file is `firmware.json` under `firmwares/<id>/`**, not
   `integration.json` under `integrations/<id>/`. Unknown fields fail
   validation, so the old field set would have been rejected outright.

2. **The four-part package is not required.** The firmware guide says in so many
   words: "A single merged image starts at offset `0`." The published
   `crossplay-<v>-sticky-full.bin` is exactly that, so the release artifact can
   be submitted as-is. The draft's note 0 ("the parts have to come from a
   dedicated `pio run -e gh_release_sticky` ... Do not go looking again") was
   wrong, and following it would have meant shipping a hand-built binary instead
   of the one users can download and verify.

3. **There is no submission form on the Playground site.** The site links to the
   registry repository; every contribution is a pull request. This was checked
   on the live page, which carries "Contribute to Playground" pointing at the
   GitHub repo.

4. **A preview image is not required to be a device photo for a partner entry.**
   The pull request template asks that "community entries include author
   attribution and a real Sticky preview; partner entries use the official logo
   as identity artwork." The shared rules also reject renders outright, so a
   simulator screenshot was not an option regardless.

## The preview image

`assets/preview.png` is generated by `make-preview.py`, which lays the card out
in HTML and photographs it in Chrome exactly as `site/make-og.py` does, so the
mark, Jersey 25 and Instrument Serif are the real ones rather than whatever a
font matcher picked. It carries no screenshot on purpose: nothing in it can be
mistaken for a photograph of a Sticky.

## Facts checked before sending

Every claim in the entry was checked against the repository at HEAD rather than
carried over from the draft:

- **The app list.** The draft named 18 items and omitted six that ship: Insider,
  Forehead, Trivia, Wavelength, Get Books and Instapaper. The shelf carries 19
  games and 5 apps (`src/apps_local/Shelf.cpp`). The README here lists all 24.
- **PLAY NEARBY.** The draft said two-device play "is untested on Sticky". That
  is wrong in both directions: Sticky-to-X4-Pro **is** verified (2026-08-26),
  and it is two _Stickys_ that are untested, for want of a second unit.
- **Version.** 1.12.11, from `platformio.ini`, matching the newest tag.
- **Flash settings.** `flashSize` 16MB, `flashMode` dio, `flashFreq` 80m were
  read out of the image header and partition table, not copied from CrossInk.
- **Licence, URLs, SD requirement, button map.** All confirmed; the four links
  in the entry were fetched and return 200.

## The one thing not settled

**The submitted 1.12.11 package has not been flashed to a Sticky.** The
registry's checklist wants the packaged firmware installed on real hardware
before review, and the newest recorded Sticky verification is v1.4.0
(2026-08-26). No Sticky was connected to this machine, and reflashing a shared
desk device is Mario's call, not a session's.

This is stated plainly in the entry README and in the pull request body rather
than papered over, and the physical-device checkboxes are left unticked. If the
maintainers want it closed before publication, the device test is the remaining
work.

## The `group` decision

`"group": "partner"` was Mario's call on 2026-08-31, on the basis that Seeed
approached the project, supplied the hardware and asked for the listing. The
contributing guide says normal third-party submissions use `community`, so the
pull request body says out loud that this is a partner entry and why, and offers
to be moved to `community` if the maintainers would rather. One field changes
and nobody is annoyed.
